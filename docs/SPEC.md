# SPEC：大学生学习助手

> 状态：MVP v1，2026-10-17 产品方向修订

## 一、产品意图

做一个以完成大学作业为首要任务的个人 AI 工作台。它读取用户上传的教材和课程资料，生成完整、可编辑、带引用的作业草稿，同时提供随时问答、答案检查和紧急复习。它不自动提交作业，也不伪造引用或运行结果。

## 二、主要用户

- 第一版：项目创建者本人，一名刚接触编程和 AI 的大学生。
- 以后可能扩展：同一学校或课程的其他学生。

## 产品定位

- 产品面向不同专业、不同课程的大学生。
- 产品本身不预装特定教材；每个用户创建自己的课程空间并上传有权使用的资料。
- 系统把“学习能力”与“具体资料”分离：上传、解析、检索、引用、辅导、复习和评估是通用能力；教材内容属于用户数据。
- 开发阶段使用团队自制的测试资料，不需要真实教材也能完成和验证产品。

## 三、准备解决的问题

1. 课程讲义、笔记和复习材料分散，不方便查找。
2. 看不懂概念时，普通搜索结果太多，也不一定基于本课程资料。
3. 面对作业题时，不知道从哪里开始，缺少逐步提示。
4. 考前不知道先复习什么，也缺少针对薄弱点的练习。
5. 通用聊天工具不了解本课程教材、教师范围和个人学习进度，回答可能与课程口径不一致。

## 四、已经确认的四种使用模式

### A. 教材问答模式

- 导入大学专业教材、讲义和个人笔记。
- 根据指定教材解释概念、公式、例题和章节关系。
- 回答中标出使用了哪份资料、章节或页码。
- 资料不足时明确说明。
- 支持追问，例如“再简单一点”“给一个例子”“这和上一章有什么关系”。

### B. 作业生成模式（默认）

- 读取题目文本、截图或教师提供的作业文件。
- 识别题目考查的知识点，并链接到教材依据。
- 默认根据题目和课程资料生成完整、可编辑的作业草稿。
- 草稿包含清晰结构、论证、假设和资料引用。
- 用户也可以切换为提示、分步讲解或答案检查。
- 根据学生已有答案指出错误、遗漏和改进方向。
- 给出最终答案时标明假设、计算过程和不确定之处，方便学生检查和改写。

### C. 紧急复习模式

- 根据考试范围、可用时间和薄弱点确定复习顺序，但不只输出计划表。
- 软件逐个讲解知识点，要求学生闭卷回答，再依据课程资料纠错。
- 学生完成一次回答与纠错后，软件主动进入下一个知识点。
- 从教材和历史错题提取高频概念、核心公式和易错点。
- 生成练习题、闪卡和限时模拟测试。
- 记录错题和薄弱知识点。
- 根据薄弱点安排后续练习。
- 在时间不足时优先保证重要知识覆盖，而不是平均复习所有章节。

### D. 自由答疑模式

- 接受学习中随时出现的问题。
- 先判断问题是否能从已导入资料回答。
- 能回答时引用教材；资料不足时区分“教材内答案”和“外部通用知识”。
- 可以在大白话、标准专业表述、例题演示和考试简答题四种表达方式之间切换。

## 五、核心工作流

### 工作流 1：教材问答

    选择课程
    → 上传教材或讲义
    → 系统解析章节和页码
    → 学生提问
    → RAG 检索相关内容
    → 生成解释并显示引用
    → 学生追问或收藏

### 工作流 2：完成一次作业辅导

    输入题目和课程规则
    → 识别题型与知识点
    → 检索教材依据
    → 选择提示或完整讲解强度
    → 分步解答
    → 学生提交自己的尝试
    → 系统检查并反馈
    → 记录薄弱点

### 工作流 3：重大考试前紧急复习

    输入考试时间、范围和剩余时间
    → 进行快速诊断
    → 按重要性和薄弱度排序
    → 选择第一个高优先级知识点
    → 讲解并要求闭卷回答
    → 依据课程资料纠错
    → 进入下一个知识点
    → 学习核心内容
    → 限时自测
    → 根据错误动态调整下一轮

## 六、第一版明确不做

- 不自动登录学校系统。
- 不自动上传或提交作业，不冒充学生身份。
- 不参加考试或绕过监考规则。
- 不编造书目、页码、论文或运行结果。
- 不一开始支持所有课程、所有文件格式和所有模型。
- 不在第一版建立复杂的多 Agent 系统。
- 不保证教材没有覆盖的问题一定能够回答。

## 七、质量与安全底线

- 资料型回答必须尽可能附带来源。
- 找不到证据时应当说“不确定”或“资料中没有找到”。
- 学习记录默认只属于用户本人，并且可以删除。
- 涉及作业时遵守课程的 AI 使用规则。
- 系统必须区分“提示”“完整讲解”“答案检查”和“提交草稿”。
- 每门课程可以记录教师允许的 AI 使用范围；规则不明确时默认采用辅导模式。
- 每个功能都要有可重复的测试或检查方法。

## 八、建议的最小可用版本（MVP）

完整目标包含四种模式。第一版先支持“一个用户创建一门课程并上传资料”，打通教材问答：

    上传一份课程资料
    → 提出一个问题
    → 系统找到相关片段
    → 用大白话解释
    → 显示资料来源
    → 用户评价是否有帮助

这条流程稳定以后，按以下顺序扩展：

1. 多个课程空间和资料管理；
2. 作业题知识点识别与分步讲解；
3. 学生答案检查与错题记录；
4. 互动式考前急救和闭卷纠错；
5. 更多资料格式和多人账户。

## 九、第一版成功标准

1. 用户可以导入至少一种文本资料。
2. 系统能针对资料内容回答问题。
3. 回答包含可识别的资料来源。
4. 资料中没有答案时，系统不会假装知道。
5. 至少准备 20 个测试问题，用来比较修改前后的正确性和引用质量。
6. 用户能够删除导入的资料。
7. 系统能保存课程名称、资料名称和章节结构。
8. 回答能够区分教材依据、模型推断和外部知识。
9. 删除课程空间后，其资料、索引和学习记录都能被清除。

## 十、当前产品优先级

1. **P0：教材导入、检索、引用和问答。**
2. **P1：作业题解析、教材知识点匹配和分步辅导。**
3. **P1：答案检查、错题记录和薄弱点更新。**
4. **P2：考试范围导入、紧急计划和自适应测验。**
5. **P3：多课程管理、图片公式识别和联网补充资料。**

## 十一、已经确定的产品决定

### 决定 1：产品与教材解耦

- 产品不依赖任何指定课程或教材。
- 用户自己建立课程空间、上传资料并拥有删除权。
- 开发和测试使用自制资料包，不等待用户上传真实资料。

### 决定 2：资料格式分阶段支持

- 当前 MVP：PPTX、Markdown 和纯文本。
- 后续：带文字层的 PDF、DOCX、扫描版 PDF 和图片 OCR。

### 决定 3：作业帮助的默认强度

- 默认生成完整、可编辑、有引用的作业草稿。
- 用户负责根据课程规则审阅和使用；系统不自动登录或提交作业。

### 决定 4：第一版在哪里运行

- 推荐：先在自己的电脑上本地运行，减少部署和隐私问题。
- 以后再决定是否做成网页。

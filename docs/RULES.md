# RULES：开发、质量与安全规则

## 产品规则

- 产品必须与具体教材解耦。
- 所有知识型回答必须区分资料依据、模型推断和外部知识。
- 没有检索证据时，不得伪造引用。
- 用户可以删除自己的课程、资料和学习记录。

## 作业生成与学习诚信规则

- 核心能力是根据课程资料生成完整、可编辑、带引用的作业草稿。
- 同时支持讲解、提示、分步解题和答案检查。
- 不自动登录课程系统，不自动提交作业，不冒充学生。
- 每门课程可以保存教师的 AI 使用规则。
- 草稿必须保留资料依据、假设和需要用户核对的部分，用户负责遵守课程规则并最终审阅。

## 资料规则

- 用户必须确认自己有权上传和处理资料。
- 不预装或公开分发受版权保护的教材。
- 不同课程和用户的数据必须隔离。
- 原始文件、解析文本和索引必须能一起删除。

## 编码规则

- 先实现小的垂直切片，再扩展功能。
- 模型、Embedding、存储和解析器通过清晰接口连接。
- 密钥只从环境变量读取，不写入代码或仓库。
- 不为未来需求提前建立复杂的多 Agent 系统。

## 测试规则

- 每个任务必须有自动测试或明确的验证命令。
- 使用自制测试资料，不在测试仓库中放入真实教材。
- 至少覆盖成功、无结果、错误格式和删除四类路径。
- 未实际运行的检查不得声称通过。

## Agent 规则

- 开始前读取当前 Task 及其引用的 SPEC、ARCH、RULES 和 CONTRACTS。
- 一次只完成当前 Task，不擅自扩大范围。
- 数据模型、公开接口、认证、隐私、删除行为和部署方式的重大变化必须写入 Decision。
- 完成后报告修改、检查证据、剩余风险和治理文档是否需要更新。
